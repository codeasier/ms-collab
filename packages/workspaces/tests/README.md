# Workspace policy tests

Run `python3 -m unittest discover -s packages/workspaces/tests -v` from the root.
`test_service.py` uses only synthetic, in-memory records and standard-library
threads. No browser, network, provider or production data is used.

## In-memory policy contract coverage

These are policy-level checks, not a completion claim for the
[28 integration acceptance cases](../../../docs/workspaces/acceptance.md).

| Contract direction | Executable coverage here | Still outside this increment |
| --- | --- | --- |
| W01–W04 | Independent module state; hidden-space errors; per-space role; shared requires membership | HTTP and real identity |
| W06–W08 | Composite resource IDs; filtering before count/page; disabled module rejects direct calls | Database, caches/cursors and MCP |
| W11–W12, W25 | Prior decision cannot write after a committed revoke; exact event barrier | SSE, worker side effects, downloads, idempotency |
| W21 | Concurrent last-two-admin demotion; atomic transfer; inactive replacement denied | Distributed/durable transaction |
| W23 | Platform operator denied business reads and self-enrollment | Platform HTTP/control authentication |
| W24 | Suspend/disable denies; archived read-only; revoked membership not reinstated | Tasks and share invalidation, which are unsupported |
| W25 | Missing/stale/invalid revisions denied without partial mutation | POST idempotency and durable commit |
| W28-related metadata only | Audit events are scoped, immutable metadata, no resource payload | Durable intent/outbox and sink failure handling |

W05, W09–W10, W13–W20, W22, W26–W27 are not claimed as implemented. There is
no general invitation, sharing, cross-space key or route implementation to test.
Server identifiers generated by creation use UUIDs, but syntax is never treated
as authorization.


## SQLite adapter coverage

`test_sqlite.py` reuses the service behavior suite with disposable SQLite stores
and adds 21 storage-specific tests. The combined discovery currently runs 94
cases: 38 original model/policy tests, 35 inherited policy cases and 21 storage
cases (the inherited issuer uniqueness case still tests the model constructor).
Separate-process checks synchronize over pipes; thread races use barriers rather
than timing sleeps. New coverage includes:

- Reopen: revisions, policy epoch, scoped audit, resources and membership persist.
- One transaction for administrator transfer, workspace creation and audit append;
  injected audit failures roll back policy, resource and epoch changes together.
- Two independent instances and processes competing on one resource revision;
  two processes attempting to demote the last two administrators.
- An old decision observed in another process cannot write after revocation has
  committed. Existing archived-space revocation cases also run on SQLite.
- Busy timeout with rollback and later retry; schema/version refusal; normal open
  does not create; bootstrap never overwrites; malformed databases, booleans and audit references fail closed.
- Abrupt process exit before commit, followed by restart/recovery; consistent
  reader snapshot prevents a writer commit until the read completes in the
  default rollback-journal mode. This does not simulate sudden power loss.

Local durable policy/resource transactions are now tested, but the outside-scope
items in the table still apply to HTTP, providers and distributed side effects.
No true login, real database-backed demo or production data was used. See the
[adapter boundary and operation contract](../SQLITE.md).
