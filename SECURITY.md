# Security Policy

## Supported Versions

The project is in early development; security fixes target the latest `main`
branch. No production security assurance or response-time SLA is promised.

## Reporting a Vulnerability

Please **do not** put vulnerabilities, credentials, private logs, or reproduction
payloads in public GitHub issues, pull requests, or Discussions.

If the repository's **Security** tab offers **Report a vulnerability**, use that
private channel. Its availability is controlled by the repository owner; this
policy does not claim that the feature has been enabled or independently tested.

If the private reporting button is unavailable, contact the maintainer through an
already-established private channel. If you do not have one, a public issue may
ask only for a secure reporting channel, with **no vulnerability details**. Wait
for a verified private destination before sharing sensitive evidence. Maintainers
must confirm a working private reporting channel before a supported release.

Include the affected version, impact, minimal sanitized reproduction and proposed
mitigation once a private channel is available. Never include working secrets.
See the [public CI trust boundary](docs/public-ci.md) for contribution safeguards.
