# 工作空间设计目标

本文件描述目标和待确定契约，不表示功能已经实现。

## 用户体验

每个产品组可使用独立空间；空间管理员管理成员、功能和配置。开发者只能访问获授权的空间与资源。公共空间用于跨组协作，其成员和可见范围也必须明确配置。

## 功能实例

同一功能可在不同空间分别启用，也可在公共空间启用。启用一个模块不意味着共享另一个空间的数据、凭据或执行权限。

## 隔离范围

隔离必须覆盖服务端授权、数据库查询、对象存储、缓存、后台任务、搜索、下载、审计及研发辅助工作区，不能只靠前端空间选择器。

共享默认关闭。管理员选择共享对象、目标空间和权限，并应能撤销和审计。公共空间不具有读取私有空间的默认特权。

## 待明确的契约

- 平台管理员、空间管理员和成员的边界与授权模型。
- 连接及凭据归属，资源标识和空间作用域。
- 公共空间准入、共享生命周期及撤销语义。
- 模块启停、后台任务和跨空间请求的行为。
- 原有单组织实例的兼容迁移与回退策略。

## 验收方向

用至少两个互相隔离的合成空间验证直接 API 请求、搜索、下载、缓存与异步任务不能越权；验证显式共享、撤销及审计。未通过这些负向测试前，不宣称具有安全的多空间隔离。

## 实施契约草案

[工作空间契约目录](workspaces/README.md) 将上述目标细化为建议的数据模型、角色权限、API/异步执行边界、共享与撤销语义、负向验收矩阵及兼容迁移计划。它不是已经实现的功能或稳定 API。

草案首版采用保守默认：公共空间需登录并显式加入；跨空间只允许经来源和目标管理员共同确认的只读版本化投影；平台治理身份不自动拥有业务数据读取权。自动全员加入、匿名公开、可写共享和应急访问仍需另行设计。
