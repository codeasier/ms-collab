## Evidence rules

- All 568 files in the fixed snapshot were checked against their Git blob hashes. This is not a candidate branch presented as main.
- Exact-main `push` runs: 36 workflows / 46 jobs succeeded. The named tests below were also located in the exact-main job logs; successful totals alone are not the evidence. Browser-script references map to their actual workflow command and successful job, with assertions inspected in source.
- Real SQLite, isolated HTTPS and actual browsers execute against synthetic identities, data and upstream transports. Neither “all mocked” nor “real second-product acceptance” describes this accurately.
- The separate 21-PNG visual review belongs to source `18943e8e505030d30132e49b5f56b440356fd04e`, whose tree equals this merge. Post-merge screenshots were **not** visually re-reviewed for this ledger. Screenshot artifacts have three-day retention, not permanent visual archival; the fixed source, [PR #66 acceptance record](https://github.com/codeasier/ms-collab/pull/66) and exact-main job references preserve the stated evidence boundary.
- **Partial synthetic** means only the named behavior has executed evidence. **Design only** means the target surface was not found in the pinned implementation. **Unverified/missing evidence** does not assert that an external provider lacks a capability. Adjacent tests marked by the row are not tests of the missing requirement.
- Package-level historical “not implemented” sections can lag later host/UI composition. Current ApplicationHost/ApplicationUI and mounted routes take precedence; existing Community/Artifact opt-in refresh and Artifact downloads are not classified as missing.

## Authority models must stay distinct

- **Pipeline:** current workspace membership and `pipelines.read` expose already stored snapshot resources in that workspace. Viewer/developer/admin read the same set. No per-snapshot readers/refresher/approver sets, candidate/published split or Artifact approval provenance. A scope hash/revision/cursor is not authority. Valid empty snapshots are stored resources, not evidence of a successful provider refresh.
- **Artifact:** per-scope reader/refresher/approver authority, exact publication and current approval provenance remain required. Byte download additionally needs its independent downloader/content binding and content-hash checks. Metadata approval is not byte permission.
- **Community:** explicit reader/refresher/approver grants and current content approval; Responsibility additionally depends on its Community read scope and its own module authority. GUI uses persistent publisher/reader fences, Assistant saved history uses current owner/dependency fences, and Research assets retain module read/sync-write rules.
- None of these same-scope mechanisms implements the cross-workspace source-offer/target-accept/projection/revoking lifecycle in W16–W20.

## First real second-product pilot: minimum decisions and evidence

This is a proposed **read-only observation pilot**, not completion of all of OBS #331 Stage 2. It must not require a new trigger, scheduler, runner, log stream, MCP execution or production cutover.

1. **Choose the product and owners.** OBS #331 names msProbe/msMemScope as candidates, not a decision. Record the ownership rule rather than guessing from an instance/repository name. Commons remains independently authorized, not an automatic union or an unimplemented cross-space share.
2. **Resolve real identity and initial authority first.** Runtime accepts only `login.mode=disabled`; initialization creates no principals/workspaces, and runtime composition does not install a bound-code exchange. Identity add/change/remove remains code-level closed. Existing invitation/initial-admin workflows address already trusted principals. Provider-owned S256/code/client/callback/replay and stable-subject evidence, isolated app/accounts and the explicit enrollment/regrant policy are prerequisites, not configuration switches. GitCode capability is **unknown/unverified**, not “PKCE unsupported”. No real provider acceptance was run.
3. **One pre-existing completed build, not a new execution.** With separately authorized read-only inputs, the smallest useful chain is member login → repository/binding → one completed run → details/tasks/duration observations → approved Artifact metadata from that build. A source manifest must connect repository/component, commit, pipeline/run/task and artifact path/digest under an explicit observation revision. Matching labels or scope hashes do not prove lineage. CI/test success is a source observation, not an independently executed release gate. Byte download can stay outside the first pilot unless its separate binding/audience is approved.
4. **Verify the actual provider contracts.** Pipeline currently has a trusted acquisition method, not host refresh/scheduler, and its evidence is consumer-side source, not the external adapter/deployment. Explicit pipeline IDs, timezone-aware times, terminal conclusions and HTTPS/public-DNS may differ from legacy loopback/HTTP, numeric timestamps or `COMPLETED`. Real Artifact region/signature/namespace behavior is unverified. GUI trusted publication and Research SourceBatch injection are not live panel/Git readers. Preserve validators rather than treating unknown records as empty success.
5. **Run the missing joint checks on the isolated real integration.** Same external IDs in the two product spaces; independent commons; actual two tabs A/B plus refresh/deep links; delayed requests; current revoke before the next page/read; operator nonmembership; module disable; source-to-observation lineage. Record fixed code, adapter version, controlled environment and each outcome. Retain “not_run” for any prerequisite not met. Existing synthetic CI and PNGs remain necessary but cannot substitute.
6. **Keep production outside this pilot.** Approved private inventory, backup, restore/revocation reconciliation, write freeze/watermark, rollback and actual hosting/proxy/filesystem acceptance remain separate. Pipeline directory parsing is bounded, but the inherited global SQLite loader still materializes state and has known corruption/capacity side channels. This is not a production scalability or strict non-interference certification.

## Next code slice, only after the minimum mapping decision

Do not add another picker or count more synthetic scenarios as a substitute for a real pilot. The next bounded code candidate is an **offline, no-write legacy ownership/ID mapping validator for one chosen read-only module**, not an importer or compatibility HTTP endpoint.
